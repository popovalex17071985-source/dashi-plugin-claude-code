# Фарпост: сбор цен конкурентов (машина с Windows)

Фарпост не пускает серверные адреса вообще: с сервера страница не отдаётся ни
разу из шести попыток. Поэтому сбор живёт на машине с Windows, а агент ходит
туда по ssh и забирает готовый файл.

## Что вообще происходит

Машина с Windows стоит у людей дома или в офисе, белого адреса у неё нет —
агент со своего сервера туда не достучится. Поэтому машина **сама** держит
постоянный канал до сервера агента, и агент ходит на неё через этот канал,
как на локальный порт.

Настраивает всё это один батник; агенту от человека нужна ровно одна вещь —
строка публичного ключа, которую батник покажет на экране.

## Разовая настройка машины

1. На машине должны стоять **Node.js LTS** и обычный **Google Chrome**.
2. Скачать и запустить **двойным кликом** `farpost-setup.bat`
   (`agent-kit/windows/farpost-setup.bat` этого репозитория).
   Батник создаёт `C:\farpost`, ставит `patchright`, качает три скрипта сбора
   и проверяет, стоит ли стена.
3. Если батник написал, что стена стоит — на той же машине выполнить
   `cd /d C:\farpost && node fp-hold.js`. Откроется окно браузера, человек
   ставит галку «я не робот», окно закрывается само. Кука ложится в профиль
   `C:\farpost\profile-farpost` и живёт около года.

Запускать батник надо под тем пользователем, который на машине работает:
браузеру нужен живой рабочий стол. Из-под службы или по ssh окно откроется в
невидимой сессии, и галку поставить будет некому.

## Что делает агент со своей стороны

1. Человек присылает строку публичного ключа с экрана батника. Агент
   добавляет её себе в `~/.ssh/authorized_keys` — это разрешает машине
   держать канал.
2. Агент прописывает себе короткое имя для машины в `~/.ssh/config`
   (порт батник называет на экране, по умолчанию 2224):

   ```
   Host farpost-win
       HostName 127.0.0.1
       Port 2224
       User <имя пользователя Windows, батник его печатает>
   ```

3. Проверка, что канал живой:

   ```
   ssh farpost-win "cd /d C:\farpost && node fp-probe.js 0"
   ```

## Как агент собирает витрину

```
ssh farpost-win "cd /d C:\farpost && node fp-scrape.js <slug>"
scp "farpost-win:C:/farpost/farpost-<slug>.json" <куда положить>
```

`<slug>` — кусок ссылки на магазин: `farpost.ru/company/AppleDubaiVL/` → `AppleDubaiVL`.

Файл: `{slug, url, ts, items:[{id, title, url, price, city, specs}]}`.
`specs` несёт цвет, память и тип связи — карточки открывать не нужно.

## Если канал отвалился

Порт на сервере перестал слушаться — значит машина выключена, перезагрузилась
или из неё вышел пользователь. Канал поднимается задачей `farpost-tunnel` при
входе в систему: человеку достаточно зайти на машину. Проверять стоит трижды с
паузой — канал переустанавливается сам и на секунды пропадает.

## Грабли, на которых уже сидели

- **Ровно 2000 позиций = обрезка.** В скрипте стоит потолок страниц; круглое
  число значит, что каталог не кончился, а упёрся в него. Цикл сам
  останавливается на первой странице без новых позиций.
- **«Failed to create a ProcessSingleton»** — профиль занят другим браузером.
  Проверить `tasklist | findstr chrome`, погасить `taskkill /F /IM chrome.exe /T`
  и запустить снова. Убийство задачи на сервере браузер на машине НЕ гасит.
- **Стена на середине сбора** — скрипт сохраняет собранное и выходит; это не
  поломка. Долбиться в стену нельзя, закроют доступ на весь день.
- **Темп.** Между страницами 4–8 секунд и передышка каждые десять страниц.
  Не ускорять: на этом и ловят.
- **Долгий сбор запускать в фоне** (`bin/bg.sh`), а не ждать в сессии: магазин
  на три тысячи позиций идёт около десяти минут.
