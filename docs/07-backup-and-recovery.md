# Бэкап и восстановление

Память агента, его характер и секреты лежат **только на сервере** — в GitHub их
нет. Умрёт сервер или забанят учётку — пропадёт всё, если нет бэкапа. Эта страница:
как включить бэкап и как поднять агента из него **одной командой** — так же просто,
как установка нового.

---

## Что нужно держать ВНЕ сервера (в менеджере паролей)

Без этого восстановить нельзя ничем и никак:

1. **Пароль от бэкапа** — установщик показывает его один раз при включении бэкапа.
   Не сохранил отдельно → облачную копию нечем расшифровать. Это самое важное.
2. **Доступ к облаку** с бэкапом (Google Drive / rclone remote `gdrive`).
3. **Доступ к GitHub** с репозиторием плагина (код оттуда, данные — из бэкапа).
4. Root-доступ к хостингу (чтобы завести новый VPS).

Токен Telegram-бота держать отдельно НЕ обязательно — он внутри бэкапа
(`deploy/channel.env`). Но если бэкапа не осталось — возьмёшь у @BotFather.

---

## Что бэкапится

`scripts/agent-backup.sh` (ставится кроном при установке, если согласился на бэкап)
раз в сутки делает один зашифрованный AES-256 архив того, чего НЕТ в git:

- `.claude/` — память, характер (CLAUDE.md), хуки, настройки;
- `secrets/` — ключи и токены;
- `state/` — состояние канала;
- `deploy/` — снимок системного: `channel.env` (токен/доступ из `/etc`),
  systemd-юнит, crontab, cron.d.

Ротация — 7 последних. Если настроен rclone-remote — копия уезжает в облако
(**смерть VPS переживёт только облачная копия**; локальная — нет). Каждый свежий
архив тут же проверяется на расшифровку: битый бэкап удаляется, а не копится.

Включить бэкап после установки, если пропустил: см. шаг «Шифрованный бэкап» в
`scripts/install-agent.sh` (перезапуск установщика ничего не ломает).

Подключить облако: под юзером агента `rclone config`, remote назвать `gdrive`.

## Восстановление — одна команда

Оба ЧП (бан учётки и смерть VPS) решаются одинаково: новый сервер → одна команда.
Разница только в том, надо ли вообще заводить новый сервер.

### Сценарий A. Забанили учётку Claude (сервер жив)

Данные и код целы — отвалился только доступ к Claude. Бэкап не нужен, только вход:

```
su - agent
claude          # выбери «Claude account» (НЕ API key), войди
exit
sudo systemctl restart dashi-<agent>
```

Напиши боту — ответил, готово. (Про риск бана под подпиской и переход на API-ключ —
см. `05-troubleshooting.md`.)

### Сценарий B. Умер VPS (нужен новый сервер)

1. Закажи новый VPS (Ubuntu 22.04+), получи root.
2. Забери код плагина:
   ```
   git clone https://github.com/popovalex17071985-source/dashi-plugin-claude-code.git
   ```
3. **Одна команда восстановления** (`gnupg`, юзера и всё остальное поставит сама):
   ```
   sudo bash dashi-plugin-claude-code/scripts/restore-agent.sh \
        --name <agent> \
        --archive gdrive:dashi-<agent>-backups/<agent>-ГГГГММДД-ЧЧММ.tar.gz.gpg \
        --pass 'ПАРОЛЬ_ИЗ_МЕНЕДЖЕРА'
   ```
   - `--archive` можно указать и локальным файлом (если скачал бэкап руками).
   - `--pass` можно не давать — спросит интерактивно.
   - Если облако (rclone) на новом сервере ещё не подключено — сначала скачай
     архив вручную и укажи локальный путь в `--archive`.

   Что делает: расшифрует → проверит пароль ДО того как что-то тронет → разложит
   память/секреты/состояние → вернёт `channel.env`, cron, systemd-юнит на место →
   доставит систему через установщик (идемпотентно) → поднимет сервис.

4. Остался **только вход в Claude** (OAuth headless не сделать):
   ```
   su - agent
   claude          # выбери тот же аккаунт Anthropic, что был раньше
   exit
   ```
5. Напиши боту в Telegram. Ответил — агент воскрес.

## Проверить, что бэкап реально рабочий

Не жди ЧП — прогони e2e-восстановление в контейнере (ничего живого не трогает):

```
bash tests/restore-agent-e2e.sh
```

Собирает архив → чистый systemd-контейнер → `restore-agent.sh` → проверяет, что
память, секреты, токен и сервис на месте. Зелёный конец = путь восстановления
рабочий целиком (кроме ручного входа в Claude).
