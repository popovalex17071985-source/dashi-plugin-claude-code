# Свой AI-агент на Codex (как Jarvis) — пошаговая инструкция для Mac

**Для кого:** для человека без опыта в программировании.
**Что получим:** личного AI-ассистента, который живёт в Telegram (пишешь ему в чат — он отвечает и делает задачи на твоём Mac), работает на подписке ChatGPT (без платного API-ключа), сам перезапускается при сбоях.
**Сколько времени:** ~1–1.5 часа спокойным шагом.

---

## Как пользоваться этой инструкцией

Идёшь строго сверху вниз, блок за блоком. Есть три типа блоков:

- В ТЕРМИНАЛ — копируешь строку и вставляешь в приложение «Терминал» на Mac, жмёшь Enter.
- В CODEX — это задача самому агенту-программисту (Codex). Вставляешь текст в окно Codex в терминале.
- В ChatGPT (браузер) — если что-то пошло не так и хочешь, чтобы тебя провели за руку. Открываешь chatgpt.com, вставляешь блок — он объяснит и подскажет.

Правило: не понял шаг — не гадай. Скопируй блок ошибки в ChatGPT и спроси «что делать».

---

## Как открыть Терминал (если не знаешь)

Нажми Cmd + Пробел, набери «Терминал», Enter. Откроется чёрное/белое окно — туда и будем вставлять команды. Вставка: Cmd + V, запуск: Enter.

# ЧАСТЬ 1. Готовим Mac (базовые инструменты)

Codex — это программа, которая ставится через «менеджер пакетов». Поставим сначала его.

### Шаг 1.1 — Ставим Homebrew (менеджер программ)

В ТЕРМИНАЛ:
```
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```
Спросит пароль от Mac — вводи (символы не видно, это нормально), Enter. Идёт пару минут.

Когда закончит — на Mac с процессором Apple (M1/M2/M3/M4) выполни ещё две строки, чтобы система «увидела» Homebrew:

В ТЕРМИНАЛ:
```
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
```

Проверка — В ТЕРМИНАЛ:
```
brew --version
```
Должна появиться строчка вида «Homebrew 4.x». Появилась — идём дальше.

Если вышла ошибка — скопируй её целиком в ChatGPT: «Ставлю Homebrew на Mac, получил такую ошибку, что делать по шагам?»

# ЧАСТЬ 2. Ставим Codex и входим по подписке

### Шаг 2.1 — Установка Codex

Самый простой способ (без лишних зависимостей) — В ТЕРМИНАЛ:
```
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

Проверка — В ТЕРМИНАЛ:
```
codex --version
```
Показал номер версии — отлично.

Если пишет «codex: command not found» — закрой Терминал полностью (Cmd+Q) и открой заново, потом снова codex --version.

### Шаг 2.2 — Вход через подписку ChatGPT (без API-ключа)

Запусти — В ТЕРМИНАЛ:
```
codex
```

При первом запуске он спросит способ входа. Выбирай «Sign in with ChatGPT» (стрелками вверх/вниз и Enter). Откроется браузер — залогинься своим аккаунтом ChatGPT (тем, где оплачена подписка Plus или Pro), подтверди доступ. Вернись в Терминал — там будет «signed in».

Важно про подписку:
- Работает на Plus и Pro. Pro даёт в разы больше лимита (примерно в 5–20 раз).
- Лимит не бесконечный: считается «скользящим окном» за 5 часов. На обычное общение хватает, но если гонять тяжёлые задачи пачками — лимит может упереться. Тогда просто подожди пару часов.
- Посмотреть остаток лимита: команда /status внутри Codex, либо на chatgpt.com/codex/settings/usage.

### Шаг 2.3 — Первый тест

Прямо в открытом окне Codex напиши что-нибудь простое, например: «Создай на рабочем столе файл hello.txt со словом Привет». Посмотри, как он работает: думает, показывает действия, спрашивает разрешение. Это и есть твой будущий агент — сейчас научим его жить в Telegram.

Выйти из Codex: набери /quit или нажми Ctrl+C дважды.

# ЧАСТЬ 3. Настраиваем «характер» и режим агента

### Шаг 3.1 — Файл настроек

У Codex есть файл настроек ~/.codex/config.toml. Создадим его с безопасными параметрами для автономной работы.

В ТЕРМИНАЛ (создаёт папку и открывает пустой файл в редакторе):
```
mkdir -p ~/.codex && nano ~/.codex/config.toml
```

Откроется простой редактор nano. Вставь туда (Cmd+V):
```
# Модель: оставь как есть, если не знаешь — это свежая
model = "gpt-5.5"

# Уровень разрешений. "never" = не переспрашивает по каждому шагу
# (нужно для агента, который работает без тебя за клавиатурой).
approval_policy = "never"

# Песочница: агент может читать и писать только в рабочей папке
# и запускать обычные локальные команды. Это безопасный режим.
sandbox_mode = "workspace-write"
```
Сохрани: Ctrl+O, Enter, потом выйди: Ctrl+X.

Про sandbox_mode = "workspace-write" — агент заперт в рабочей папке, наружу не лезет. Есть режим danger-full-access (полный доступ к Mac) — не включай его, пока не будешь понимать, что делаешь.

### Шаг 3.2 — «Душа» агента (файл AGENTS.md)

Codex читает файл AGENTS.md как постоянную инструкцию — это как «характер и правила» твоего ассистента (аналог того, что у Jarvis лежит в CLAUDE.md). Сделаем глобальный.

В ТЕРМИНАЛ:
```
nano ~/.codex/AGENTS.md
```

Вставь свой вариант (можешь править под себя — имя, стиль, задачи):
```
# Кто ты

Ты — мой личный AI-ассистент. Зовут тебя [ИМЯ].
Общаешься со мной в Telegram. Я читаю Telegram, не терминал —
поэтому всё, что хочешь мне сказать, должно уйти ответом в чат.

# Как отвечаешь
- По-русски, коротко и по делу, без воды и извинений.
- Сначала суть/результат, потом пояснения.
- Если задача непонятна — задай уточняющий вопрос, не выдумывай.

# Что можешь
- Отвечать на вопросы, искать информацию, писать тексты.
- Работать с файлами в рабочей папке.
- Выполнять команды на Mac (в пределах песочницы).

# Правила безопасности
- Никогда не удаляй файлы без явной просьбы.
- Не показывай пароли и ключи.
- Сомневаешься в опасном действии — сначала спроси меня.
```
Сохрани (Ctrl+O, Enter, Ctrl+X).

Хочешь более прокачанный «характер» (как у Jarvis — со стилем, приоритетами, памятью)? Вставь в ChatGPT: «Я делаю личного AI-агента на Codex. Помоги написать файл AGENTS.md: опиши характер, стиль общения по-русски, правила безопасности и мои задачи — [опиши чем занимаешься]. Дай готовый текст, который я скопирую.»

# ЧАСТЬ 4. Заводим Telegram-бота

Агент будет общаться через бота. Создаём его.

### Шаг 4.1 — Создать бота через BotFather

1. Открой Telegram, в поиске набери @BotFather, открой (с синей галочкой).
2. Нажми Start, отправь команду /newbot.
3. Придумай имя (любое, например «Мой Ассистент») и username (должен заканчиваться на bot, например sanya_assist_bot).
4. BotFather пришлёт токен — длинная строка вида «1234567890:AAE...». Это пароль к боту, никому не показывай.

### Шаг 4.2 — Узнать свой chat_id

Чтобы бот отвечал именно тебе, нужен твой ID.
1. В поиске Telegram найди @userinfobot, нажми Start.
2. Он пришлёт твой Id — число (например 140141496). Запиши.

### Шаг 4.3 — Первое сообщение боту

Найди своего свежесозданного бота по username, нажми Start и напиши ему «привет». Без этого бот не сможет тебе писать первым.

# ЧАСТЬ 5. Собираем мост Telegram — Codex

Тут самое интересное. Мы не будем писать код руками — попросим самого Codex его написать. Это и есть суть агента-программиста.

### Шаг 5.1 — Создаём рабочую папку

В ТЕРМИНАЛ:
```
mkdir -p ~/codex-bot && cd ~/codex-bot
```

### Шаг 5.2 — Кладём токен и ID в отдельный файл

В ТЕРМИНАЛ (замени значения на свои — токен от BotFather и твой chat_id):
```
nano ~/codex-bot/.env
```
Вставь (свои значения после знака равно):
```
TELEGRAM_TOKEN=сюда_токен_от_BotFather
TELEGRAM_CHAT_ID=сюда_твой_id
```
Сохрани (Ctrl+O, Enter, Ctrl+X).

### Шаг 5.3 — Просим Codex написать мост

Запусти Codex прямо в этой папке — В ТЕРМИНАЛ:
```
cd ~/codex-bot && codex
```

Теперь вставь в окно Codex это задание.

В CODEX:
```
Напиши мне скрипт-мост между Telegram и тобой (Codex CLI) на bash.
Файл назови bridge.sh, положи в текущую папку ~/codex-bot.

Логика простая (long-polling loop):
1. Читай TELEGRAM_TOKEN и TELEGRAM_CHAT_ID из файла .env в этой папке.
2. В бесконечном цикле запрашивай новые сообщения у Telegram
   через getUpdates с offset (long polling, timeout 30 сек).
3. Реагируй только на сообщения от TELEGRAM_CHAT_ID, остальные игнорь.
4. На каждое новое сообщение:
   - запускай: codex -a never exec --sandbox workspace-write "текст сообщения"
   - бери финальный ответ из stdout
   - отправляй его обратно в тот же чат через Telegram sendMessage.
5. Если ответ длиннее 4000 символов — режь на части.
6. Сохраняй offset в файл .offset, чтобы не терять сообщения при перезапуске.
7. Все ошибки логируй в err.log, но цикл не останавливай.

Используй только curl и стандартные утилиты Mac, без установки лишнего.
Сделай файл исполняемым (chmod +x bridge.sh).
После создания — коротко объясни, как его запустить.
```

Codex напишет bridge.sh, покажет действия — разрешай. В конце он объяснит запуск.

Если Codex сделал что-то, что не работает — скопируй ошибку из терминала и вставь обратно в Codex: «При запуске bridge.sh получаю такую ошибку: [вставить]. Почини.» Он умеет чинить свой же код.

### Шаг 5.4 — Проверяем мост вручную

Выйди из Codex (/quit). Запусти мост — В ТЕРМИНАЛ:
```
cd ~/codex-bot && ./bridge.sh
```
Теперь напиши своему боту в Telegram «привет, ты живой?». Через несколько секунд должен прийти ответ. Работает — поздравляю, агент живой.

Останови пока что: в терминале Ctrl+C.

# ЧАСТЬ 6. Делаем так, чтобы работал сам (24/7 и автозапуск)

Сейчас агент живёт только пока открыт терминал. Научим Mac держать его всегда и перезапускать при сбоях. На Mac это делает launchd.

### Шаг 6.1 — Файл автозапуска

В ТЕРМИНАЛ:
```
nano ~/Library/LaunchAgents/com.codexbot.plist
```
Вставь (замени ИМЯ на имя пользователя Mac — узнать: команда whoami):
```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.codexbot</string>
    <key>ProgramArguments</key>
    <array>
        <string>/Users/ИМЯ/codex-bot/bridge.sh</string>
    </array>
    <key>RunAtLoad</key>
    <true/>
    <key>KeepAlive</key>
    <true/>
    <key>StandardOutPath</key>
    <string>/Users/ИМЯ/codex-bot/out.log</string>
    <key>StandardErrorPath</key>
    <string>/Users/ИМЯ/codex-bot/err.log</string>
    <key>EnvironmentVariables</key>
    <dict>
        <key>PATH</key>
        <string>/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin</string>
    </dict>
</dict>
</plist>
```
Сохрани (Ctrl+O, Enter, Ctrl+X).

KeepAlive = true — это и есть первая линия «ремонтника»: если процесс упал или его закрыли, macOS сам поднимет его заново. PATH прописан вручную, потому что автозапуск не знает, где лежит codex.

### Шаг 6.2 — Включаем

В ТЕРМИНАЛ:
```
launchctl load ~/Library/LaunchAgents/com.codexbot.plist
```
Теперь агент работает в фоне и стартует сам при включении Mac. Проверь — напиши боту в Telegram.

Выключить (если понадобится):
```
launchctl unload ~/Library/LaunchAgents/com.codexbot.plist
```

Внимание: Mac должен быть включён и не спать, чтобы бот отвечал. Для «всегда онлайн» держи Mac подключённым к сети и в настройках энергосбережения запрети сон при питании от сети (или поставь приложение вроде Amphetamine).

# ЧАСТЬ 7. Агент-ремонтник (watchdog)

KeepAlive из Части 6 перезапускает процесс, если он совсем упал. Но бывает хитрее: процесс жив, а бот «завис» и не отвечает. Сделаем умного ремонтника, который это ловит, чинит и сообщает тебе.

### Шаг 7.1 — Просим Codex написать ремонтника

В ТЕРМИНАЛ:
```
cd ~/codex-bot && codex
```

В CODEX:
```
Напиши скрипт-ремонтник watchdog.sh в папке ~/codex-bot.
Задача: следить за здоровьем моего Telegram-бота (bridge.sh).

Логика:
1. Читай TELEGRAM_TOKEN и TELEGRAM_CHAT_ID из .env.
2. Проверяй, запущен ли процесс bridge.sh (pgrep).
3. Проверяй err.log: если за последние 5 минут там появились
   повторяющиеся ошибки — считай это сбоем.
4. Если бот мёртв или сбоит:
   - перезапусти его через launchctl
     (launchctl unload затем load плиста com.codexbot),
   - отправь мне в Telegram сообщение вида
     "Бот падал, перезапустил. Причина: [последняя ошибка из err.log]".
5. Если всё хорошо — молчи, ничего не шли.
Сделай файл исполняемым. Объясни, как повесить его на запуск раз в 5 минут.
```

Codex напишет watchdog.sh и подскажет, как поставить его в расписание (через launchd с ключом StartInterval или через crontab). Следуй его инструкции — она будет под твою систему.

Итог: два уровня защиты. KeepAlive поднимает упавший процесс мгновенно. watchdog.sh раз в 5 минут проверяет «а точно ли он живой и отвечает», чинит зависания и пишет тебе в Telegram, что случилось. Это и есть твой агент-ремонтник.

### Шаг 7.2 (по желанию) — Ремонтник, который сам чинит код

Если хочешь, чтобы ремонтник не просто перезапускал, а разбирался в причине:

В CODEX:
```
Улучши watchdog.sh: если бот падает 3 раза подряд по одной и той же
ошибке, запусти codex exec с заданием "прочитай err.log, найди причину
падения bridge.sh и почини код", а результат (что нашёл и что изменил)
пришли мне в Telegram. Ничего не удаляй без бэкапа — перед правкой
делай копию bridge.sh в bridge.sh.bak.
```

Теперь агент чинит сам себя и отчитывается тебе. Осторожно: это даёт агенту право менять свой код — держи бэкапы (они прописаны в задании).

# ЧАСТЬ 8. Память (чтобы помнил контекст)

По умолчанию каждый ответ — «с чистого листа». Чтобы агент помнил ваши договорённости, заведи файл памяти.

В CODEX (в папке ~/codex-bot):
```
Заведи файл memory.md в этой папке для долгой памяти.
Доработай bridge.sh так, чтобы:
- перед каждым запросом ты подкладывал содержимое memory.md в контекст;
- если я в сообщении пишу "запомни: ..." — ты дописывал факт в memory.md.
Не раздувай файл: одна строка — один факт.
```

Это простая, но рабочая память. Хочешь серьёзнее (как у Jarvis — с индексом и категориями) — это уже отдельный проект, вернёшься к нему позже.

# Шпаргалка: частые проблемы

- «command not found: codex» — закрой терминал (Cmd+Q), открой заново. Не помогло — переустанови Часть 2.1.
- Бот не отвечает — проверь, что Mac не спит. Глянь err.log: cat ~/codex-bot/err.log. Скопируй ошибку в ChatGPT.
- «Отвечает всем подряд» — в .env неверный TELEGRAM_CHAT_ID. Проверь через @userinfobot.
- Уперся лимит подписки — подожди пару часов (окно 5 ч) либо перейди на Pro. Остаток: /status в Codex.
- Хочу поменять характер — отредактируй ~/.codex/AGENTS.md.

## Итоговая карта (что где лежит)

```
~/.codex/config.toml        — настройки Codex (модель, режим)
~/.codex/AGENTS.md          — характер/правила агента
~/codex-bot/.env            — токен бота и твой chat_id (СЕКРЕТ)
~/codex-bot/bridge.sh       — мост Telegram — Codex
~/codex-bot/watchdog.sh     — ремонтник
~/codex-bot/memory.md       — память
~/codex-bot/err.log         — журнал ошибок
~/Library/LaunchAgents/com.codexbot.plist  — автозапуск 24/7
```

Готово. У тебя есть личный агент на Codex, живущий в Telegram, работающий на подписке ChatGPT, с автозапуском и ремонтником.
