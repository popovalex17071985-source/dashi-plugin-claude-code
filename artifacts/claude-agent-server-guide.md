# Свой AI-агент на Claude Code, на сервере — пошаговая инструкция для новичка

**Для кого:** для человека без опыта в программировании.
**Что получим:** личного AI-ассистента (как Jarvis), который живёт в Telegram и работает на **сервере (VPS)** — значит отвечает круглосуточно, даже когда твой компьютер выключен. Собран на **Claude Code** и работает на **подписке Claude** (Pro/Max), без платного API-ключа. Сам перезапускается при сбоях.
**Сколько времени:** ~1.5–2 часа спокойным шагом.

---

## Как пользоваться этой инструкцией

Идёшь строго сверху вниз, блок за блоком. Типы блоков:

- **В ТЕРМИНАЛ** — команда, которую вставляешь в терминал (сначала на своём Mac/ПК, потом — внутри сервера). Enter.
- **НА СЕРВЕРЕ** — то же, но выполняется уже внутри сервера (после того как подключишься по SSH).
- **В CLAUDE** — задача самому агенту-программисту Claude Code (вставляешь текст в его окно).
- **В БРАУЗЕРЕ** — действие на сайте (аренда сервера, авторизация).

Правило: не понял шаг или вылезла ошибка — не гадай. Скопируй ошибку в claude.ai (или прямо агенту) и спроси «что делать по шагам».

# ЧАСТЬ 1. Арендуем сервер (VPS)

Сервер — это чужой компьютер в дата-центре, который работает всегда. Подойдёт самый дешёвый.

### Шаг 1.1 — Взять VPS
1. Зайди к любому провайдеру VPS (Timeweb, Selectel, VDSina, Aeza, Hetzner — любой).
2. Возьми тариф: **Ubuntu 22.04 или 24.04**, минимум **2 ГБ RAM** (лучше 4 ГБ — Claude Code любит память), 1–2 CPU. ~300–600 ₽/мес.
3. После оплаты провайдер пришлёт: **IP-адрес** сервера, **логин** (обычно `root`) и **пароль**. Запиши их.

### Шаг 1.2 — Зайти на сервер
На своём Mac открой Терминал (Cmd+Пробел → «Терминал»). На Windows — приложение «Terminal» или PowerShell.

**В ТЕРМИНАЛ** (подставь свой IP):
```
ssh root@ТВОЙ_IP
```
Спросит «yes/no» — напиши `yes`. Спросит пароль — вставь тот, что прислал провайдер (символы не видно — это нормально), Enter.

Появилась строка вида `root@server:~#` — ты внутри сервера. Дальше всё выполняем **НА СЕРВЕРЕ**.

---

# ЧАСТЬ 2. Ставим Node.js и Claude Code

Claude Code — это программа на Node.js. Ставим Node, потом сам Claude Code.

### Шаг 2.1 — Обновить систему и поставить Node.js
**НА СЕРВЕРЕ** (по одной, ждём каждую):
```
apt update && apt -y upgrade
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs git
```
Проверка:
```
node --version
```
Должно показать `v22.x`. Показало — идём дальше.

### Шаг 2.2 — Поставить Claude Code
**НА СЕРВЕРЕ:**
```
npm install -g @anthropic-ai/claude-code
```
Проверка:
```
claude --version
```
Показал номер версии — отлично.

> Совет по безопасности (по желанию): работать под `root` не идеально. Можно завести отдельного пользователя (`adduser agent`, затем `su - agent`) и всё делать под ним. Для старта можно и под root — но знай, что агент получит права root.

# ЧАСТЬ 3. Вход по подписке Claude (без API-ключа)

Тут единственный по-настоящему хитрый момент: сервер без браузера, а вход в подписку идёт через браузер. Два способа — выбери один.

### Способ А (проще) — вход прямо на сервере с кодом
**НА СЕРВЕРЕ:**
```
claude
```
При первом запуске выбери вход **Claude account (подписка)**, НЕ API-ключ. Claude покажет **ссылку** и попросит код.
1. Скопируй ссылку, открой её **в браузере на своём компьютере**.
2. Залогинься аккаунтом, где оплачена подписка (Pro/Max), подтверди доступ.
3. Браузер покажет **код авторизации** — скопируй его и вставь обратно в терминал сервера, Enter.

Готово — «logged in». Если экран входа не предложил код, а только localhost-ссылку — используй Способ Б.

### Способ Б (надёжный) — перенести вход с компьютера
1. Поставь Claude Code **на свой Mac** (`npm install -g @anthropic-ai/claude-code`), запусти `claude`, войди по подписке — на компьютере с браузером это проходит гладко.
2. На Mac файл входа лежит в `~/.claude/`. Скопируй папку на сервер **В ТЕРМИНАЛ** (на своём Mac, не на сервере):
```
scp -r ~/.claude root@ТВОЙ_IP:~/
```
3. Вернись на сервер, запусти `claude` — уже залогинен.

> Подписка: Pro тянет лёгкие задачи, **Max** — в разы больше лимита, для агента 24/7 бери Max. Лимит считается скользящим окном; упрётся — подожди или подними план. Проверить: `/status` внутри Claude.

### Шаг 3.1 — Первый тест
**НА СЕРВЕРЕ:**
```
claude -p "Скажи привет одной строкой и назови текущую дату"
```
Флаг `-p` = «ответь и выйди» (без интерактивного окна). Пришёл ответ — агент работает. Это и есть режим, которым мы свяжем его с Telegram.

# ЧАСТЬ 4. Характер агента (файл CLAUDE.md)

Claude Code читает файл `CLAUDE.md` как постоянную инструкцию — характер и правила (у Jarvis это ровно так и устроено). Сделаем глобальный.

**НА СЕРВЕРЕ:**
```
nano ~/.claude/CLAUDE.md
```
Вставь (правь под себя — имя, стиль, задачи):
```
# Кто ты
Ты — мой личный AI-ассистент, зовут тебя [ИМЯ].
Общаешься со мной в Telegram. Я читаю Telegram, НЕ терминал —
значит всё, что хочешь сказать мне, должно уйти ответом в чат.

# Как отвечаешь
- По-русски, коротко и по делу, без воды и извинений.
- Сначала суть/результат, потом пояснения.
- Непонятна задача — задай уточняющий вопрос, не выдумывай.

# Что можешь
- Отвечать, искать, писать тексты, работать с файлами, выполнять команды.

# Безопасность
- Не удаляй файлы без явной просьбы. Не показывай пароли/ключи.
- Сомневаешься в опасном действии — сначала спроси меня.
```
Сохрани: Ctrl+O, Enter, выйди: Ctrl+X.

Хочешь характер посерьёзнее (стиль, приоритеты, память как у Jarvis) — попроси самого Claude: «Помоги написать CLAUDE.md для моего агента: [чем занимаешься, какой стиль]. Дай готовый текст».

# ЧАСТЬ 5. Заводим Telegram-бота

### Шаг 5.1 — Создать бота
1. В Telegram найди **@BotFather** (синяя галочка), нажми Start, отправь `/newbot`.
2. Придумай имя и username (заканчивается на `bot`).
3. BotFather пришлёт **токен** (вида `1234567890:AAE...`). Это пароль к боту — никому.

### Шаг 5.2 — Узнать свой chat_id
1. Найди **@userinfobot**, нажми Start.
2. Он пришлёт твой **Id** (число, напр. 140141496). Запиши.

### Шаг 5.3 — Написать боту
Найди своего бота по username, нажми Start и напиши «привет» — без этого бот не сможет писать тебе первым.

# ЧАСТЬ 6. Собираем мост Telegram ↔ Claude Code

Код руками не пишем — попросим сам Claude Code. В этом и суть агента-программиста.

### Шаг 6.1 — Рабочая папка и секреты
**НА СЕРВЕРЕ:**
```
mkdir -p ~/agent && cd ~/agent
nano ~/agent/.env
```
Вставь свои значения:
```
TELEGRAM_TOKEN=токен_от_BotFather
TELEGRAM_CHAT_ID=твой_id
```
Сохрани (Ctrl+O, Enter, Ctrl+X).

### Шаг 6.2 — Просим Claude написать мост
**НА СЕРВЕРЕ:**
```
cd ~/agent && claude --dangerously-skip-permissions
```
(`--dangerously-skip-permissions` = агент не переспрашивает по каждому шагу; нужно для работы без тебя за клавиатурой.)

**В CLAUDE:**
```
Напиши bash-скрипт-мост bridge.sh в текущей папке ~/agent между Telegram и Claude Code.

Логика (long-polling):
1. Читай TELEGRAM_TOKEN и TELEGRAM_CHAT_ID из .env в этой папке.
2. В бесконечном цикле опрашивай Telegram getUpdates с offset (long polling, timeout 30 сек).
3. Реагируй ТОЛЬКО на сообщения от TELEGRAM_CHAT_ID, остальные игнорь.
4. На каждое новое сообщение запускай:
     claude -p "текст сообщения" --dangerously-skip-permissions --continue
   («--continue» — чтобы агент помнил прошлые сообщения одной беседой), бери stdout как ответ.
5. Отправляй ответ обратно в тот же чат через Telegram sendMessage. Ответ >4000 символов — режь на части.
6. Сохраняй offset в .offset, чтобы не терять сообщения при перезапуске.
7. Ошибки пиши в err.log, но цикл не останавливай.

Только curl и стандартные утилиты, без лишних установок. Сделай bridge.sh исполняемым и объясни, как запустить.
```
Claude напишет `bridge.sh`. Если что-то не работает — скопируй ошибку обратно в окно Claude: «При запуске bridge.sh ошибка: [вставь]. Почини». Он чинит свой же код.

### Шаг 6.3 — Проверка вручную
Выйди из Claude (`/exit` или Ctrl+C). **НА СЕРВЕРЕ:**
```
cd ~/agent && ./bridge.sh
```
Напиши боту в Telegram «ты живой?». Через несколько секунд придёт ответ. Работает — останови пока: Ctrl+C.

# ЧАСТЬ 7. Автозапуск 24/7 (systemd)

На сервере «вечный» процесс держит **systemd** — сам стартует при перезагрузке и поднимает после падения.

### Шаг 7.1 — Файл службы
**НА СЕРВЕРЕ** (если ставил под пользователя, а не root — поправь User и пути):
```
nano /etc/systemd/system/agent.service
```
Вставь:
```
[Unit]
Description=Telegram Claude agent
After=network-online.target

[Service]
Type=simple
User=root
WorkingDirectory=/root/agent
ExecStart=/root/agent/bridge.sh
Restart=always
RestartSec=5
Environment=PATH=/usr/bin:/usr/local/bin:/root/.npm-global/bin

[Install]
WantedBy=multi-user.target
```
Сохрани (Ctrl+O, Enter, Ctrl+X).

### Шаг 7.2 — Включить
**НА СЕРВЕРЕ:**
```
systemctl daemon-reload
systemctl enable --now agent
systemctl status agent --no-pager
```
Зелёное `active (running)` — агент в фоне и стартует сам. `Restart=always` — первая линия ремонтника: упал процесс, systemd поднимет за 5 секунд.

Полезное:
```
journalctl -u agent -f      # смотреть живой лог
systemctl restart agent     # перезапустить
systemctl stop agent        # остановить
```

# ЧАСТЬ 8. Агент-ремонтник (watchdog)

`Restart=always` поднимает упавший процесс. Но бывает: процесс жив, а бот «завис». Сделаем умного ремонтника.

**НА СЕРВЕРЕ:**
```
cd ~/agent && claude --dangerously-skip-permissions
```
**В CLAUDE:**
```
Напиши скрипт-ремонтник watchdog.sh в ~/agent.
Логика:
1. Читай TELEGRAM_TOKEN и TELEGRAM_CHAT_ID из .env.
2. Проверяй, что служба agent жива: systemctl is-active agent.
3. Проверяй err.log: если за последние 5 минут повторяются одинаковые ошибки — считай это зависанием.
4. Если бот мёртв или завис: systemctl restart agent и пришли мне в Telegram
   "Бот падал, перезапустил. Причина: [последняя ошибка из err.log]".
5. Если всё хорошо — молчи.
Сделай исполняемым. Дай команды, чтобы повесить его на запуск раз в 5 минут через systemd timer.
```
Следуй его инструкции по systemd timer. Итог — два уровня защиты: systemd мгновенно поднимает упавший процесс, watchdog раз в 5 минут ловит зависания, чинит и пишет тебе в Telegram.

> По желанию — самочинящийся: «Улучши watchdog.sh: если бот падает 3 раза подряд по одной ошибке — запусти `claude -p "прочитай err.log, найди причину падения bridge.sh и почини"`, результат пришли мне в Telegram. Перед правкой делай копию bridge.sh.bak, ничего не удаляй без бэкапа».

# ЧАСТЬ 9. Память

`--continue` в мосте уже держит одну непрерывную беседу. Для долгой памяти (переживает перезапуск) — заведи файл.

**В CLAUDE** (в папке ~/agent):
```
Заведи memory.md в этой папке. Доработай bridge.sh так, чтобы:
- перед каждым запросом подкладывать содержимое memory.md в контекст (через --append-system-prompt или дописывая в текст запроса);
- если я пишу "запомни: ..." — дописывать факт в memory.md.
Не раздувай: одна строка — один факт.
```

# Шпаргалка: частые проблемы

- **`claude: command not found`** — переоткрой сессию SSH; не помогло — повтори Шаг 2.2. В systemd пропиши полный PATH (уже в примере).
- **Бот молчит** — `systemctl status agent`, потом `journalctl -u agent -n 50` и `cat ~/agent/err.log`. Ошибку — в claude.ai.
- **Отвечает всем подряд** — неверный `TELEGRAM_CHAT_ID` в `.env` (проверь через @userinfobot).
- **Уперся лимит подписки** — окно скользящее, подожди или подними до Max. Остаток: `/status`.
- **Слетел вход** — повтори Часть 3 (или заново скопируй `~/.claude` со своего Mac).
- **Поменять характер** — правь `~/.claude/CLAUDE.md`.

## Итоговая карта (что где лежит)
```
~/.claude/CLAUDE.md                 — характер/правила агента
~/.claude/ (вход)                   — авторизация подписки (СЕКРЕТ)
~/agent/.env                        — токен бота и chat_id (СЕКРЕТ)
~/agent/bridge.sh                   — мост Telegram ↔ Claude Code
~/agent/watchdog.sh                 — ремонтник
~/agent/memory.md                   — память
~/agent/err.log                     — журнал ошибок
/etc/systemd/system/agent.service   — автозапуск 24/7
```

Готово. Личный агент на **Claude Code**, на **сервере**, в **Telegram**, на **подписке Claude**, с автозапуском и ремонтником — работает круглосуточно без твоего компьютера.
