# Свой AI-агент как Jarvis — с нуля за 15 минут (v3)

**Сервер + Claude Code на подписке + плагин dashi + Telegram. Работает 24/7,
понимает голос, помнит контекст, сам переподнимается, ноль кнопок
подтверждения.**

Для человека без опыта. Установка одной командой; руками — только то, что за
тебя не сделает никто.

> v3 (19.08.2026): четырнадцать ручных шагов свёрнуты в скрипт `install-agent.sh`.
> Прежний пошаговый путь никуда не делся — он ниже, в разделе «Ручной путь»,
> и нужен, когда что-то пошло не так и хочется понимать, что вообще происходит.

---

## Что приготовить (10 минут)

1. **VPS** — любой, Ubuntu 22.04+, 2 ГБ памяти хватает. Нужен root-доступ по SSH.
2. **Бот в Telegram** — @BotFather → `/newbot` → имя и username на `bot` → пришлёт
   **токен**. Потом @userinfobot → Start → пришлёт **твой id** (число).
   Найди своего бота и нажми **Start** — без этого он не сможет написать первым.
3. **Подписка Claude** — Pro или Max. Для круглосуточной работы бери Max.
4. *(необязательно)* **Ключ Groq** для распознавания голосовых: console.groq.com →
   Create API Key, начинается на `gsk_`. Бесплатно.

> ⚠️ Токен бота — это пароль. Засветил в чате или на скрине — сразу @BotFather →
> `/revoke` и получи новый.

## Установка (одна команда)

Зайди на сервер root'ом и выполни:

```
curl -fsSL https://raw.githubusercontent.com/popovalex17071985-source/dashi-plugin-claude-code/main/scripts/install-agent.sh -o install-agent.sh
sudo bash install-agent.sh
```

Скрипт спросит имя агента, токен, твой id и ключ Groq — и дальше всё сделает
сам: систему, Node.js, Claude Code, отдельного пользователя, Bun, workspace,
плагин, конфиг, хуки, автозапуск.

Посреди установки он остановится и попросит войти в Claude — это единственное,
что нельзя автоматизировать:

```
su - agent
claude
```

Выбери **«Claude account»** (НЕ «API key»), открой показанную ссылку в браузере
на своём компьютере, войди аккаунтом с подпиской, скопируй код обратно в
терминал. Затем `Ctrl+C`, `exit` — и запусти установщик ещё раз той же командой.
Он доделает остальное и поднимет сервис.

> ⚠️ Из России вход через сайт claude.ai может не открыться даже с VPN. Не мучай
> claude.ai: способ выше работает, потому что это OAuth-страница, а не личный
> кабинет. Скопировать вход с Mac (`scp ~/.claude`) или из десктоп-приложения
> НЕ выйдет — у приложения и у CLI токены разные.

Скрипт идемпотентный: запускай сколько угодно раз, он доделывает недостающее и
не трогает готовое. Прервался, потерял связь, ошибся — просто запусти снова.

## Проверка

Напиши боту в Telegram — он ответит.

Проверить, что автономия работает: попроси «создай файл /tmp/proba.txt с текстом
привет и прочитай его». Сделал и отчитался без единого запроса подтверждения —
всё в строю.

Полезное:

```
systemctl status dashi-<имя>          # жив ли
journalctl -u dashi-<имя> -n 50       # что в логах
systemctl restart dashi-<имя>         # перезапустить
su - agent -c 'tmux attach -t channel-<имя>'   # заглянуть внутрь сессии
```

## Что дальше (по желанию, каждое — 5 минут)

**Характер.** Установщик кладёт болванку `CLAUDE.md`. Попроси агента переписать
её под себя: «Проведи со мной интервью и перепиши свой CLAUDE.md: кто я, чем
занимаюсь, как ко мне обращаться, как ты должен отвечать».

**Память между сессиями.** Одним сообщением боту:

> Организуй себе долгую память. Создай рядом с CLAUDE.md папку memory/ и в ней
> MEMORY.md — индекс, одна строка на факт. Каждый факт — свой файл с шапкой
> (name, description, type: user/project/feedback/reference) и телом-фактом.
> В CLAUDE.md впиши: при старте читаю MEMORY.md; узнал факт или получил правку —
> сохраняю файл и строку в индекс; память против реальности — реальность выше.
> Заполни сразу файл обо мне: кто я, чем занимаюсь, как обращаться, часовой пояс.

**Семантическая память (OpenViking).** Файловые слои агент получает сразу — их
хватает надолго. Когда фактов накопится столько, что индекс перестанет
помещаться в голове, сверху ставится OpenViking: он ищет по смыслу, а не по
строке в индексе. Это отдельный сервис, ему нужен Docker:

```
claude plugin marketplace add Castor6/openviking-plugins
claude plugin install claude-code-memory-plugin@openviking-plugin
```

Дальше ему нужен свой конфиг и поднятый docker-compose — поэтому в установщик я
это не зашивал: слои от него не зависят и подключается он сбоку, не ломая уже
накопленное. Включать имеет смысл не в первый день.

**Голос.** Не вписал ключ Groq при установке — добавь строку `GROQ_API_KEY=gsk_...`
в `/etc/dashi-plugin/<имя>/channel.env` и перезапусти сервис.

**Бот-ремонтник** — страховка на случай, когда основной агент завис. Тупой
питоновский скрипт вторым ботом, команды `/status`, `/restart`, `/logs`. Смысл
его тупости в том, что он не виснет вместе с основным. Инструкция — в разделе
«Ручной путь», Часть G.

Правило номер один: вылезла ошибка — не гадай. Скопируй её целиком своему
рабочему агенту (или в claude.ai) и спроси «что делать по шагам».

# Ручной путь

Дальше — прежний пошаговый гайд: то же самое, но руками. Нужен, если установщик
не подошёл (нестандартная система, свои пути), если хочется понимать каждый шаг,
или для разбора поломки.

## Условные обозначения

- **[ТЕРМИНАЛ]** — команда на твоём Mac/ПК (до захода на сервер).
- **[СЕРВЕР]** — команда внутри сервера (после SSH).
- **[БОТУ]** — задача самому агенту (пишешь ему в Telegram).
- **[БРАУЗЕР]** — действие на сайте.

---

## Три решения, которые экономят день (прочти до старта)

Мы набили эти шишки — ты не набивай:

1. **Агент живёт под ОТДЕЛЬНЫМ не-root пользователем, а НЕ под root.**
   Полная автономия («агент сам всё делает, ничего не подтверждаешь») под root
   технически НЕВОЗМОЖНА — Claude Code отказывается работать в режиме без
   подтверждений от имени root. Поэтому мы сразу создаём юзера `agent` и всё
   ставим под ним. Если поставить под root, а потом захотеть автономию —
   придётся переносить всё заново (мы так и потеряли время).

2. **Длинный код НЕ копируется через Telegram надёжно.** Копипаст кода из чата в
   редактор на сервере глючит (особенно на Mac). Поэтому файлы со скриптами
   пусть пишет САМ агент прямо на диск сервера — не через чат.

3. **Вход в Claude делаем прямо на сервере** (способ с браузером). Копирование
   логина с Mac и вход через приложение — НЕ работают для CLI.

# ЧАСТЬ A. Сервер, пользователь, Claude Code, вход

## Шаг 1 — Арендовать VPS

Зачем: сервер работает всегда — агент онлайн 24/7 без твоего компьютера.

- Провайдер любой (VDSina, Timeweb, Selectel, Aeza, Hetzner).
- Тариф: **Ubuntu 22.04 или 24.04**, минимум **2 ГБ RAM** (лучше 4), 1–2 CPU.
- Провайдер пришлёт **IP, логин (root), пароль** — запиши.

## Шаг 2 — Зайти на сервер

Открой Терминал (Mac: Cmd+Пробел → «Терминал». Windows: Terminal/PowerShell).

**[ТЕРМИНАЛ]** (подставь свой IP):
```
ssh root@ТВОЙ_IP
```
На «yes/no» → `yes`, затем пароль (символы при вводе не видно — это норма).
Появилась строка `root@...#` — ты внутри. Дальше всё **[СЕРВЕР]**.

## Шаг 3 — Обновить систему и поставить Node.js + Claude Code

**[СЕРВЕР]** (по одной строке):
```
apt update && apt -y upgrade
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs git unzip
npm install -g @anthropic-ai/claude-code
```
Проверка: `claude --version` — показал версию, идём дальше.

> ⚠️ ГРАБЛЯ: `unzip` часто не стоит по умолчанию, а он нужен установщику Bun
> дальше. Поэтому ставим сразу (`unzip` в строке выше).

## Шаг 4 — Создать отдельного пользователя `agent` (КЛЮЧЕВОЙ шаг)

Зачем: см. «решение №1» выше — под root не будет полной автономии.

**[СЕРВЕР]**:
```
adduser --disabled-password --gecos "" agent
```
Теперь входим под него:
```
su - agent
```
Строка сменилась на `agent@...$` — теперь ты работаешь как `agent`.

> ⚠️ ГРАБЛЯ: ВСЁ ниже (Bun, плагин, вход в Claude, конфиг) делаем из-под
> `agent`, не из-под root. Если случайно окажешься под root (`root@...#`) —
> вернись: `su - agent`.

## Шаг 5 — Вход в Claude по подписке (без API-ключа)

Зачем: агент работает на твоей подписке (Pro/Max; для 24/7 бери Max).

**[СЕРВЕР]** (под `agent`):
```
claude
```
Выбери вход **«Claude account (подписка)»**, НЕ «API key». Claude покажет
ссылку — открой её в браузере на своём компьютере, залогинься аккаунтом с
подпиской, скопируй показанный код и вставь обратно в терминал сервера.

Проверка: `claude -p "скажи привет одной строкой"` — пришёл ответ, вход есть.
Выйди из этого пробного запуска (Ctrl+C).

> ⚠️ ГРАБЛЯ (Россия): вход через сайт claude.ai может не открываться без VPN, а с
> некоторыми VPN — тоже. Не мучай claude.ai. Способ выше (`claude` на сервере →
> ссылка → код) — рабочий: авторизуешься через OAuth-страницу, а не через личный
> кабинет. Копировать вход с Mac (`scp ~/.claude ...`) или войти в десктоп-
> приложение и «перенести» токен — НЕ работает: у приложения и у CLI токены
> разные.

# ЧАСТЬ B. Плагин dashi (мост Telegram ↔ агент)

Зачем именно плагин, а не самописный бот: он держит ОДНУ живую сессию Claude
Code и пушит в неё сообщения из Telegram. Что даёт: расход внутри подписки (а не
поштучная оплата API), память между сообщениями, из коробки — приём голосовых,
пузырёк прогресса, авто-рестарт связи, безопасная отправка (прячет секреты,
режет длинное).

## Шаг 6 — Bun (движок плагина)

**[СЕРВЕР]** (под `agent`):
```
curl -fsSL https://bun.sh/install | bash
```
Перелогинься, чтобы `bun` подхватился в PATH:
```
exit          # вышли из agent обратно в root
su - agent    # снова зашли — теперь bun в PATH
bun --version
```
Показал версию — ок.

## Шаг 7 — Папки агента (workspace + секреты)

Зачем: одна «личность» = один workspace со своим CLAUDE.md; секреты держим
отдельно и закрытыми.

**[СЕРВЕР]**:
```
mkdir -p ~/.claude-lab/myagent/.claude ~/.claude-lab/myagent/secrets
cd ~/.claude-lab/myagent/.claude
```

## Шаг 8 — Склонировать плагин ВНУТРЬ workspace

> ⚠️ ГРАБЛЯ: расположение критично. Claude Code грузит характер (CLAUDE.md) по
> текущей папке, а сам плагин ищется относительным путём. Кладём внутрь `.claude`
> и запускаем всё потом ИЗ ПАПКИ `plugin` (см. Шаг 13). Иначе — ошибка «no MCP
> server configured with that name».

**[СЕРВЕР]** (ты в `~/.claude-lab/myagent/.claude`):
```
git clone https://github.com/qwwiwi/dashi-plugin-claude-code.git
cd dashi-plugin-claude-code/plugin
bun install
```

## Шаг 9 — Telegram-бот и твой ID

**[БРАУЗЕР/Telegram]**:
1. @BotFather → Start → `/newbot` → имя и username (должен кончаться на `bot`) →
   пришлёт **ТОКЕН** (пароль к боту, никому не показывай).
2. @userinfobot → Start → пришлёт твой **ID** (число).
3. Найди своего бота, нажми **Start**, напиши «привет» (без этого бот не сможет
   писать тебе первым).

> ⚠️ ГРАБЛЯ: если токен где-то засветился (скинул в чат, на скрине) — сразу
> @BotFather → `/revoke` → получи новый. Утёкший токен = чужой доступ к боту.

## Шаг 10 — Конфиг (channel.env)

> ⚠️ ГРАБЛЯ: не набирай имена переменных вручную из головы — легко ошибиться.
> Копируй готовый пример и меняй только ЗНАЧЕНИЯ.

**[СЕРВЕР]** (из папки `plugin`):
```
cp ../examples/channel.env.example ~/.claude-lab/myagent/secrets/channel.env
chmod 600 ~/.claude-lab/myagent/secrets/channel.env
nano ~/.claude-lab/myagent/secrets/channel.env
```
Заполни значения (имена переменных уже в файле, не трогай их):
```
TELEGRAM_BOT_TOKEN=токен_от_BotFather
TELEGRAM_ALLOWED_USER_IDS=твой_id
TELEGRAM_ALLOWED_CHAT_IDS=твой_id
GROQ_API_KEY=ключ_groq            # для голоса; см. Часть D
```
Сохрани: Ctrl+O, Enter, Ctrl+X.

`TELEGRAM_ALLOWED_USER_IDS` — единственный барьер доступа: бот слушает только эти
id. Больше туда никого не добавляй.

## Шаг 11 — Характер агента (CLAUDE.md)

Зачем: «душа» — имя, стиль, правила. То, что делает агента личностью.

**[СЕРВЕР]**:
```
nano ~/.claude-lab/myagent/.claude/CLAUDE.md
```
Минимум впиши: имя, стиль (по-русски, коротко, суть вперёд), правила
безопасности, и **ГЛАВНОЕ правило канала**:

> «Я общаюсь через Telegram, а не через терминал. Каждый ответ, вопрос,
> подтверждение и итог я отправляю пользователю инструментом reply. Текст в
> терминале пользователь не видит.»

Хочешь богаче — попроси самого Claude написать CLAUDE.md под твои задачи (см.
приём с интервью в Части E).

## Шаг 12 — Установить hooks (обязательно)

Зачем: без хуков нет пузырька прогресса, зеркала терминала и авто-дошылки
ответа.

**[СЕРВЕР]** (из папки `plugin`):
```
bash scripts/install-hooks.sh --settings ~/.claude/settings.json \
  --chat-id ТВОЙ_ID --webhook-url http://127.0.0.1:8089/hooks/agent \
  --agent-id dashi-channel
```

## Шаг 13 — Первый запуск (проверка, что мост живой)

> ⚠️ ГРАБЛЯ: запускать ТОЛЬКО из папки `plugin` — иначе «no MCP server».

**[СЕРВЕР]** (ты в `~/.claude-lab/myagent/.claude/dashi-plugin-claude-code/plugin`):
```
set -a
. ~/.claude-lab/myagent/secrets/channel.env
set +a
claude --dangerously-load-development-channels server:dashi-channel
```
При первом запуске Claude задаст 2 вопроса (внешние импорты + dev-каналы) —
ответь `1` на оба, это разово.

Теперь напиши боту в Telegram — он должен ответить. Работает — гаси пробный
запуск (Ctrl+C) и переходи к автономии и автозапуску.

## Шаг 14 — Диагностика «доктором» (если что-то не так)

Read-only проверка всего моста, ничего не ломает. Гоняй первым при любой
проблеме.

**[СЕРВЕР]** (из папки `plugin`):
```
bun ../skills/doctor-dashi-plugin/scripts/doctor.ts --plugin-dir "$PWD"
```
Код выхода 0 = всё чисто.

# ЧАСТЬ C. Полная автономия (ноль кнопок)

Зачем: чтобы агент сам делал действия и НЕ дёргал тебя подтверждениями на каждый
чих.

> ⚠️ ГЛАВНАЯ ГРАБЛЯ ДНЯ: режим «без подтверждений»
> (`--dangerously-skip-permissions`) под **root НЕ работает** — Claude выходит с
> ошибкой «cannot be used with root», сессия падает, systemd молча зациклится.
> Именно поэтому в Шаге 4 мы создали не-root юзера `agent`. Под ним автономия
> включается штатно. Если ты всё делал под `agent` — просто добавь флаг в запуск
> (уже вшит в systemd-юнит ниже, Часть F). Ничего отдельно менять не нужно.

Как проверить, что автономия реально работает: напиши боту «создай файл
/tmp/proba.txt с текстом привет и прочитай его». Если он сделал и отчитался БЕЗ
единого запроса подтверждения — автономия в строю.

# ЧАСТЬ D. Голос (расшифровка голосовых)

Зачем: без ключа Groq текст работает, а голос — нет.

1. **[БРАУЗЕР]** console.groq.com → залогинься → «Create API Key» → скопируй
   (начинается на `gsk_`). Бесплатно, лимитов на голос с запасом хватает.
2. Впиши ключ в `channel.env` (строка `GROQ_API_KEY=...`, Шаг 10) и перезапусти
   сервис (`systemctl restart ...` из Части F).

# ЧАСТЬ E. Автозапуск 24/7 (systemd)

Зачем: агент стартует сам при перезагрузке и поднимается после сбоя. Claude
Code — интерактивная программа, ей нужен «экран», поэтому держим её в tmux.

**[СЕРВЕР]** (под root — юниты живут в системной папке; выйди из agent: `exit`):
```
nano /etc/systemd/system/dashi.service
```
Вставь (подставь своего юзера/пути, если менял; здесь юзер `agent`):
```
[Unit]
Description=Dashi agent (Telegram to Claude Code)
After=network-online.target

[Service]
User=agent
WorkingDirectory=/home/agent/.claude-lab/myagent/.claude/dashi-plugin-claude-code/plugin
EnvironmentFile=/home/agent/.claude-lab/myagent/secrets/channel.env
Environment=HOME=/home/agent
Environment=PATH=/home/agent/.bun/bin:/usr/local/bin:/usr/bin:/bin
Type=forking
ExecStart=/usr/bin/tmux new-session -d -s dashi /usr/bin/claude --dangerously-skip-permissions --dangerously-load-development-channels server:dashi-channel
ExecStartPost=/bin/sh -c 'sleep 8 && /usr/bin/tmux send-keys -t dashi Enter && sleep 2 && /usr/bin/tmux send-keys -t dashi Enter'
ExecStop=/usr/bin/tmux kill-session -t dashi
Restart=on-failure
RestartSec=15s

[Install]
WantedBy=multi-user.target
```
Включи:
```
systemctl daemon-reload
systemctl enable --now dashi
systemctl status dashi        # ждём active (running)
```

> ⚠️ ГРАБЛЯ: `ExecStartPost` с двумя `Enter` нужен, чтобы «нажать» те самые 2
> первых вопроса Claude (внешние импорты + dev-каналы) при холодном старте.
> Без него сессия зависает на вопросе и бот молчит.
> ⚠️ ГРАБЛЯ: `Type=forking` + tmux обязательны — Claude нужен псевдотерминал,
> напрямую как демон он не живёт.
> Проверь автозапуск после перезагрузки: `systemctl is-enabled dashi` → `enabled`.

Приём для богатого характера: скорми боту файл-интервью — попроси задать по
порядку вопросы (чем занимаешься, как обращаться, стиль, часовой пояс, запреты) и
записать ответы в CLAUDE.md. Тогда характер соберётся сам, без ручной писанины.

# ЧАСТЬ F. Память агента (помнит между сессиями)

Зачем: чтобы агент помнил тебя, проект и твои правки, а не начинал с нуля.

Самый простой рабочий вариант — файловая память. Скорми боту **одним
сообщением** ТЗ:

**[БОТУ]**:
```
Организуй себе долгую память. Создай в моём workspace (рядом с CLAUDE.md):
- папку memory/ и в ней файл MEMORY.md — индекс, одна строка на факт
  «- [Заголовок](файл.md) — короткий хук»;
- каждый факт — свой файл memory/имя.md с шапкой (name, description,
  type: user/project/feedback/reference) и телом-фактом.
В CLAUDE.md впиши правила: при старте читаю MEMORY.md; узнал факт или получил
правку — сохраняю новый файл + строку в индекс; память против реальности —
реальность выше.
Заполни сразу файл обо мне: кто я, чем занимаюсь, как обращаться, часовой пояс.
```
Дальше просто говоришь «запомни, что…» — копит сам.

Хочешь многослойку (как у продвинутых агентов): добавь папку `core/` с файлами
`USER.md`, `rules.md` (правила и правки), `decisions.md` (решения ~14 дней),
`handoff.md` (последние 5 итогов), `LEARNINGS.md` (уроки), а в CLAUDE.md через
`@include` подключи ТОЛЬКО лёгкие `USER.md` и `rules.md` — остальное агент читает
по требованию, чтоб не жечь контекст. Тоже отдаётся боту одним ТЗ.

# ЧАСТЬ G. Бот-ремонтник (страховка на случай, когда основной завис)

Зачем: если основной агент завис и молчит — через него же ты его не починишь.
Нужен ОТДЕЛЬНЫЙ бот на отдельном процессе, который умеет его перезапускать.

Ключевой принцип: ремонтник — **тупой командный скрипт, НЕ на Claude**. В этом
его надёжность: голый скрипт на пяти командах не виснет, а значит всегда сможет
поднять основного. Будь он на том же движке — завис бы вместе с ним.

**Шаг 1 — второй бот.** @BotFather → `/newbot` → новый токен. Найди его, Start,
«привет».

**Шаг 2 — код напишет сам основной агент** (пока он живой). Скорми ему:

**[БОТУ]**:
```
Напиши мне бота-ремонтника — отдельный сторож за сервисом dashi.
1. Python-скрипт на long-polling (только requests). Слушает ВТОРОГО бота.
   Токен второго бота и мой user_id читает из /home/agent/repairbot.env
   (REPAIR_BOT_TOKEN и REPAIR_OWNER_ID).
2. Реагирует ТОЛЬКО на мой user_id, остальных игнорит.
3. Команды: /ping (ответ «жив»), /status (systemctl is-active dashi + аптайм),
   /restart, /stop, /start, /logs (последние 40 строк journalctl -u dashi).
   Результат шлёт мне в чат, длинное режет до 4000 символов.
4. Юнит repairbot.service от root, автозапуск, Restart=on-failure.
Ты под юзером agent и в /root, /etc писать не можешь. Поэтому запиши файлы в мою
папку: скрипт в /home/agent/repairbot.py, юнит в /home/agent/repairbot.service.
Потом дай мне точные команды, которыми я от root перенесу их на места и включу.
```

> ⚠️ ГРАБЛЯ: не проси бота вываливать код в ЧАТ и копировать вручную — длинный
> код через Telegram копируется криво. Пусть пишет файлами на диск (у юзера
> `agent` в своей папке права есть), а ты переносишь их от root.

**Шаг 3 — установка от root** (основной агент выдаст токен-плейсхолдеры, ты
подставишь). **[СЕРВЕР]** под root:
```
cp /home/agent/repairbot.py /root/repairbot.py
cp /home/agent/repairbot.service /etc/systemd/system/repairbot.service
nano /root/repairbot.env
      # REPAIR_BOT_TOKEN=токен_второго_бота
      # REPAIR_OWNER_ID=твой_id
chmod 600 /root/repairbot.env
systemctl daemon-reload
systemctl enable --now repairbot
systemctl status repairbot     # ждём active (running)
```

**Шаг 4 — проверка.** Напиши ВТОРОМУ боту `/ping` (ответит «жив») и `/status`
(покажет состояние основного). Отвечает — страховка на месте.

**Как чинить, если /restart не помогает:**
1. `/logs` — глянь причину (частое: перегруз сервера/кончилась память, протух
   логин Claude, битый конфиг).
2. По SSH: `systemctl status dashi`, `journalctl -u dashi -n 50`. Если висит в
   петле — реальная ошибка часто в самом окне Claude: `tmux attach -t dashi`.
3. Глухо висит весь сервер — `reboot` целиком (оба сервиса в автозапуске,
   встанут сами).

# Железное правило безопасности

Любую починку/переустановку МОСТА делай из **терминала сервера, НЕ из Telegram**.
Ты меняешь тот самый канал, которым шлёшь команды — сломается на середине,
Telegram замолчит, и чинить будет нечем. Порядок: терминал на сервере → правка →
доктор → тестовое сообщение → только потом ушёл. (Именно для аварий из терминала
и существует бот-ремонтник — он единственное исключение, потому что он отдельный
процесс.)

# Быстрый траблшутинг (симптом → причина → фикс)

| Симптом | Причина | Фикс |
|---|---|---|
| Бот молчит после запуска | Запустил не из папки `plugin` | `cd .../plugin`, запускай оттуда |
| «no MCP server configured» | То же — неверная папка | Запуск из `plugin` |
| Claude падает сразу, tmux пуст | Режим без подтверждений под root | Перенести на не-root юзера (Часть C) |
| Спрашивает подтверждения на всё | Нет `--dangerously-skip-permissions` / под root | Не-root юзер + флаг в юните |
| Вход в Claude не проходит | Пытаешься через claude.ai/приложение | OAuth прямо на сервере (Шаг 5) |
| Голос не расшифровывается | Нет `GROQ_API_KEY` | Впиши ключ, перезапусти сервис |
| Код из чата вставляется криво | Копипаст длинного кода в терминал | Пусть агент пишет файлы на диск |
| Сессия зависла на старте | Не «нажаты» 2 первых вопроса | `ExecStartPost` с двумя Enter |
| Основной завис, не отвечает | Разное | Ремонтнику `/restart`, не помог — `reboot` |
